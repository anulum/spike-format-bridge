# Component boundaries

The metadata command reads a fixed schema, repository-domain.json and the
development lock. It validates exact repository identity, local-scaffold
maturity, empty capabilities and declared source hashes. It writes no inventory.

The source-provenance command reads tracked and nonignored untracked files
through native Git. It validates native source notices, invisible Markdown
headers, same-cohort JSON sidecars and exact original licence and asset bytes.
Missing tracked content and unavailable Git remain unavailable results.

Inventory generation consumes validated metadata through the original verifier.
Inventory verification separately checks the generated source binding and full
repository tree. Neither operation will supply evidence of recording conversion.

The planned domain pipeline is source reader, canonical integer event chunks,
declared transforms, destination writer and whole-logical-payload round-trip
comparison. Side streams, source clocks and typed metadata remain explicit.
Required unrepresentable payloads make conversion infeasible.

Evidence Manifest Toolkit remains the shared sealing owner. Spike Log remains
the native-container owner. The conversion implementation will consume their
qualified public interfaces instead of duplicating them.

Workflow policy binds actual native job sources and complete category results;
dependency alignment observes the own exact installed graph and executable
provenance. Documentation checks render the actual API and local references.
These controls use finite regular-file/strict JSON readers and authored reports,
while the original declaration and source verifiers preserve their exact refusal
codes and human CLI. Preflight consumes the same canonical machine protocol for
all six component gates and records every real required child result.
