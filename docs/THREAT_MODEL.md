# Local validation trust boundaries

The current surface reads local metadata and a development lock. The maintained
checker and its fixed expected identity are trusted inputs. Received declaration
files are checked before a result is reported.

Protected assets include original source bytes, accurate capability declarations
and the distinction between repository checks and scientific evidence. A changed
declaration cannot grant device access, signing authority or format support.

The JSON reader bounds bytes and refuses duplicate keys, nonfinite values,
invalid Unicode and excessive nesting. Expected file names are fixed by the
checker. Missing inputs produce unavailable results; malformed declarations
produce refusal results. Neither outcome is a successful scientific verdict.

Host permissions and installed dependency integrity are separate controls.
Complete repository inventory and future recording codecs require their own
boundary validation. No network endpoint, device interface or credential input
is exposed by the current command.
